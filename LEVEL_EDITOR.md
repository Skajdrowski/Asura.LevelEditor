# Asura 2005 Level Editor

`AsuraLevelEditor.exe` is a native Win32 editor for both new OBJ-authored levels and original Sniper Elite 2005 `.PC` levels. It renders the environment, authors spawn points, lights, sounds, and source-backed pickups, stores the working level in a binary `.alev` project, and exports one final target-game `.PC`. Entity JSON is not used by this path.

## IDA results

### Port 13338 — Sniper Elite 2005 target, no PDB

- `sub_43F250`, identified by `Asura_Chunk_Loaders.cpp`, is the top-level chunk dispatcher.
- `sub_441690` accepts target `SKYB` versions 1 through 7; the editor exposes the version-6 and version-7 layouts used by the source levels. The serialized version does not select sky geometry: `sub_49D000` renders the same six-face camera-centered cube for both v6 and v7. Version 7 only adds the right-face compatibility flag after the v6 cloud and back-face flags. `mp_06d.pc` is v7 with both face flags clear. `sub_49D000` applies the right-face flag first, otherwise the back-face flag, and leaves all face UVs unchanged when both flags are clear. `sub_49CEE0` resolves all eight texture slots. Slots 0–5 feed the six fixed background faces and slots 6–7 feed the optional cloud pass; individual levels may reuse a texture or leave any slot empty. The OBJ constructor's default convention leaves slot 0 empty and writes `fr`, `lf`, `bk`, `rt`, and `up` to slots 1–5, while the original `mp_01a.pc` fills all six background slots. `sub_423210` builds the separate cloud layer's tessellated sphere, and `sub_49D600` flattens and offsets it into a camera-centered ellipsoid with repeating spherical UVs and two animated samples at `time/64` and `time/128`. The editor viewport reproduces that slot layout, face table, cloud geometry, and animation rates; its cloud sampler uses an equivalent-density pole-safe projection to avoid exposing the target mesh's longitude singularity as radial wedges when the editor camera looks through it.
- `sub_441310` handles `RSCF`. Type 0 enters the PC platform dispatcher `sub_49E340`.
- `sub_49E340` switches on the PC platform subtype. The target meanings are 0 Environment, 1 Character, 2 Object, 3 ReplaceableSounds, 4 unhandled/skipped, and 5 ObjectHierarchy. This is not the later PDB's Xbox 360 subtype enum.
- `sub_49E5C0` is the subtype-0 PC Environment reader used by the new **Open .PC** path. It reads the module, strip, and buffer counts; allocates the exact 12-byte and 20-byte target tables; then creates 36-byte-stride vertex buffers and 16-bit index buffers for each serialized block.
- `sub_43C360` loads the separate `AEPR` extended-rain particle system, and `sub_41C820` reads its raining/active flags plus sheltered regions. `sub_41D4D0` doubles the distance of each camera-centered emitter layer, while `sub_41CA60` advances its falling particles. `sub_51E8C0` and `sub_522860` select level-specific original `\specialfx\rn_p01a.tga`-style sprites; the editor resolves their copied DDS counterparts, rotates their authored streaks into falling droplets, and renders animated, depth-tested layers whenever the editable rain setting is enabled.
- Environment material resolution is stream-ordered. `sub_441CE0` accepts `TEXT` v0-v3 and replaces the original-texture conversion table; `Asura_Chunk_Material::Process` at `0x440440` accepts `MTRL` v0-v1 and converts each serialized texture ordinal through the active `TEXT` table; `sub_49E5C0` then converts every Env strip's signed original material ordinal through that active `MTRL` table. The editor follows the same `TEXT -> MTRL -> Env` chain and resolves the resulting names to embedded type-2 texture `RSCF`s. The target's `Asura_PC_Material_V1` is exactly 12 bytes: original texture index, material flags, and PDB-named project flags whose low byte is used as a gameplay surface/material type—not an RGB colour. In target Env `sub_48C860`, both material-flag-2/TXFL branches converge on blend mode 1 (`SRC_ALPHA/INV_SRC_ALPHA`) and combiner 13: fragments alpha-test texture alpha above `10/255`, blend baked diffuse RGB by that texture alpha, and write depth. The equal-depth base pass then uses combiner 8 with `DESTCOLOR/SRCCOLOR`, giving `saturate(2 * texture.rgb * prelightFramebuffer.rgb)`. MCP2's ObjectHierarchy renderer at `sub_489C30` supplies the missing opacity distinction: flag-2 textures with TXFL bit `0x8` clear use alpha test, opaque blending, and combiner 1 (`MODULATE2X texture/diffuse`), while bit `0x8` set uses background blending. MCP1's `Asura_Xbox360_EnvironmentRenderer::Render(bool)` and `Asura_MaterialResponse::BLEND_MODE` independently separate opaque from background-blended strips and do not apply a texture-colour normalization stage. The `.PC` preview therefore treats a flag-2/TXFL-bit-clear material without wet, additive, or reflection flags as a solid cutout: texture alpha controls coverage and surviving pixels use the exact `saturate(2 * texture.rgb * prelight.rgb)` opaque equation. Flag-`0x4` alpha cutouts such as `mp_06d.pc`'s flag-`0x6` `fencing2.tga` use this same cutout path, preserving transparent holes while avoiding the brightness-amplifying detail multipass. True blended materials and flag `0x1`, `0x80`, or `0x4000` multipass materials retain the target Env equations. Non-cutout flag `0x4` adds `\graphicnovel\detail.dds` at `uv*32` through combiner 10; flag `0x1` replays the base texture with `SRC_ALPHA/ONE`; and flag `0x80` generates camera-space reflection coordinates, samples `\specialfx\spheremap1.bmp`, blends it over white using the base texture alpha carried in `CURRENT`, then multiplies the framebuffer with blend mode 3 (`DESTCOLOR/ZERO`). When WTHR byte `+0x15` enables wet weather and the material also has flag `0x4000`, the target substitutes `\specialfx\splash.bmp` at `uv*2+offset` for the flag-`0x4` auxiliary stage. Target `sub_488D90` builds the adjustable hardware gamma ramp with `2*g*x*(1-x)+x*x`; the default option value 50 supplies `g=0.5`, so the ramp is identity. The reference PDB independently names the alpha-test request and fixes its normalized reference at `0.039215688`.
- `sub_49E420` is the subtype-1 PC Character reader used by `MPChars.asr`. After a padded character/skin name it reads four `uint32_t` values, creates a vertex buffer with a 64-byte stride and a 16-bit index buffer, then uploads `vertexCount * 64` and `indexCount * 2` bytes. The first value is `indexCount - 2`, proving that the index data is one stitched triangle strip whose degenerate windows join its sections.
- `sub_49EA00` is the subtype-5 PC ObjectHierarchy reader used for pickup previews. After its padded resource name it reads strip, vertex, and index counts; every strip is the target's 20-byte triangle-count/start-index/material-hash/lowest-vertex/vertex-count record. Vertices have a 32-byte position/normal/UV layout and indices are 16-bit triangle strips. A physical pickup's `m_uSkinID` is the lowercase 31-multiply hash of that hierarchy name, which resolves the instance directly to resources such as `stickgrenade`, `dp28`, and `ammo_rifle` embedded in the opened `.PC`.
- The `russian_soldier9` character resource contains 2,064 vertices, 4,683 strip indices, and 2,743 nondegenerate triangles. `german_soldier5` contains 2,136 vertices, 4,895 strip indices, and 2,835 nondegenerate triangles. Position and normal are the first two three-float fields of each target vertex. Their Y coordinates use the target's negative-up convention, so the preview applies the same game-to-editor Y conversion as placed entities.
- The target Environment reader uses 12-byte module records, 20-byte strip records, and 36-byte vertices. Source assertions and the material conversion path prove the strip fields are triangle count, start index, signed original material index, lowest vertex used, and vertex count. `-1` means no material; non-negative values index the target's original-to-runtime conversion table. These target-only records are named `Asura_PC_EnvironmentRenderer_*`; the PDB's 52-byte Xbox 360 strip is not wire-compatible.
- `sub_43C470` reads the complete 32-byte version-0 fog record. The later PDB version adds an extra graph-fog point, but confirms the shared names `xColour`, `fNearPlane`, `fFarPlane`, `fValueAtFarPlane`, and `fSkyboxValue`. FOG is retained only as untouched source data; the level-editor preview deliberately does not render this legacy PlayStation 2 feature.
- `sub_43EB50` is the `LITE` loader. For chunk versions 3 through 5 it allocates and reads `0x6C` bytes per `Asura_Light`; `sub_43EF00` then copies the fields through `m_uFlags` at offset `0x50`, maintains the old-position/range fields, and sets `HasChanged` at `0x68`.
- `sub_4432B0` converts positive-range `LITE` records with flag `0x04` into the target's static photon set; `sub_443810` evaluates linear radial falloff `max(0, 1-distance/range)`. The environment draw calls `sub_444050` with the static-photon query disabled and the dynamic-photon query enabled, so adding imported `LITE` records to the editor's Env shader would double-light baked vertex diffuse. The editor keeps the named `AffectsEnvironment=0x08` flag editable for byte-correct authoring, but does not use it as a preview brightness control.
- Target light-flag use proves the little-endian wire masks: `HasCorona=0x01`, `UseBoundingBox=0x20`, and `IsShadowVolume=0x40`. The intervening flags follow the reversed low-bit ordering of the Xbox PDB declaration, so the source stores a raw `uint32_t` plus explicit PC masks instead of compiler-dependent bitfields.
- `sub_43B0D0` reads an ENTI body and calls `sub_43AC20`.
- `sub_43AC20` is the engine entity factory; project classifications fall through to the Sniper factory at `sub_5A4B00`.
- `sub_43B110` is the ENTI serializer. The exact wire header is `ENTI`, total size, version, flags, GUID, `uint16 classification`, `uint16 padding`, followed by the virtual class writer. The full fixed header is 24 bytes.
- `sub_4563F0` validates serialized tool-authored GUIDs in the inclusive range `0x000186A0` through `0x00030D3F`; `0x00030D40` and above belong to game-created entities. Newly authored pickups, spawns, and lights now allocate unique IDs only from the tool range. Before export, the editor also remaps pre-existing editor-authored ENTI records from an older `.alev` project if they persisted the previous invalid allocator state.
- Project classification `0x803A` reaches `sub_591A40`, whose source assertion names the class `Snipe_ServerEntity_SpawnPoint`.
- The `0x803A` constructor accepts payload version 0 and reads position, direction, spawn index, posture, team mask, game-mode mask, and a spawn timer. Target checks at `sub_591570`/`sub_591580` prove the two bit masks; the update path at `sub_591560` proves the final value is a timer, not the previously guessed activation radius.
- The activatable base reader accepts version 2 and reads its active flag before `Asura_ServerEntity_SoundController` reads its own version 0 and phonon GUID. These are separate version fields in the ENTI payload.
- Classification `0x0008` is the 2005 physical pickup object. Its target reader chain is `sub_57DF80` -> `sub_57C2F0` -> `sub_4665A0` -> `sub_57EE10` -> `sub_57B5F0` -> `sub_465B10`; the matching writer chain is `sub_57DF70` -> `sub_57C270` -> `sub_466560` -> `sub_57EDB0` -> `sub_57B570` -> `sub_465A00`. Together they prove the complete fixed `0x94`-byte, zero-link payload: Pickup v2, Asura pickup v2, static object v3, Asura static object v0, Snipe physical object v7, and Asura physical object v7. The final 68-byte physical record is position, quaternion, health, file/skin/animation/animation-file IDs, animation flags, bounding-box index, a ten-bit state field, physical flags, and animation timer, followed by the blocked-navigation-link count. Retail files sometimes contain uninitialized garbage above the ten valid state bits, so synthetic records mask those high bits. The first Asura-pickup value is the gameplay item ID; `sub_57C570` corroborates the enum by switching on the explosive/throwable IDs `0x08`, `0x09`, `0x0A`, `0x0B`, `0x0F`, `0x1C`, `0x1E`, and `0x26`. The editor now names pickups from `SNIPE_ITEM_ID_2005` instead of displaying only that number. MCP1's `Asura_ServerEntity_PhysicalObject::ChunkDataV10` independently names the shared physical fields and confirms that `m_uFileID` is the object-file asset ID, not the item enum or narrowly a skeleton ID.
- `sub_50F840` converts gameplay item IDs into the target attachment/model names. `sub_5DDA60` hashes that name for the skin ID, while `sub_5DE100` appends `_rest` and hashes it for the animation ID. `sub_403FB0` is the target's lowercase, backslash-to-slash, multiply-by-31 hash. The retail uncompressed `mp_01a.pc` `RSFL` proves the remaining file IDs are hashes of `Characters\<model>\<model>.ASR` and `Characters\<model>\Anims\<model>_rest.ASR`; for example MG42 resolves to file `5AD130DC`, skin `00331598`, animation `0642BE1B`, and animation file `D525EE6E`. MCP1's named `Asura_GetHashID_IgnoreExtension` independently corroborates the same case/slash normalization and multiply-by-31 loop. Consequently the editor can construct a catalog entry from a donor's embedded ObjectHierarchy resource even when that donor has no placed ENTI instance of the item.
- Classification `0x804F` reaches the assassination-target reader at `sub_579E60`/`sub_579880`. Its version-0 record also derives from the same static/physical chain, so its position and quaternion are imported at their class-specific offsets.
- Classification `0x8052` reaches `sub_590650`. It copies a fixed version-0 record made of a 3-by-3 orientation matrix and its transpose, an interleaved `Asura_Bounding_Box`, the box centre, and flags. `sub_582A00` independently proves that layout by initializing the two matrices and computing the centre from the six bounds. The editor uses that centre as the marker position and keeps the bounds synchronized when it is moved.

### Port 13337 — 2008 PDB-rich `AvP3_Retail.xex`

- The PDB local types confirm a 16-byte `Asura_Chunk_Header`: the anonymous `ID`/`TextID[4]` union is at `0x00`, followed by `Size`, `Version`, and `Flags` at `0x04`, `0x08`, and `0x0C`.
- `Asura_Chunk_ResourceFile_Xbox360_Environment::Process` at `0x823CB2A8` confirms the reference build's analogous environment-resource flow (counted renderer records followed by vertex/index buffers). Its 52-byte Xbox 360 strip and 68-byte vertex formats remain reference-only; the importer deliberately uses MCP2's 2005 PC sizes above.
- `Asura_Skybox::Platform_Initialise` at `0x823FB270`, `Asura_Skybox::Platform_Render` at `0x823FB6A0`, and `CreateVerticesForFace` at `0x823FAF30` confirm the camera-centered six-face construction. Its later-build base-face UV order differs from the exact 2005 PC order above, so it is reference geometry rather than the viewport's UV source.
- `Asura_Bounding_Box` is six interleaved scalar bounds—`MinX`, `MaxX`, `MinY`, `MaxY`, `MinZ`, `MaxZ`—rather than two three-component vectors. Target assertions independently name `MinX` and `MaxX`, so the 24-byte layout is shared by both builds.
- `Asura_ServerEntity_PhysicalObject::ChunkData` confirms the shared leading layout used by the older target physical record: `m_xPosition`, `m_xOrientation`, `m_fHealth`, then the file, skin, animation, animation-file, animation flags, bounding-box index, and physical flags fields. The 2005 reader's version-7 record is shorter than the later PDB version, so MCP2 remains the authority for its exact size and offsets.
- `Asura_Xbox360_ObjectHierarchyRenderer::Hierarchy` and its typed `Strip` corroborate the reference build's analogous hierarchy/index-buffer renderer. Its 24-byte Xbox strip includes an added bone index and two material hashes, so only the rendering role transfers; MCP2's exact 20-byte PC record remains the wire authority.
- `Asura_Chunk_Lights::Process` at `0x821FA448` accepts version 5, allocates `0x6C` bytes per light, and reads exactly that many bytes. `Asura_Light::Set` at `0x821FA380` confirms `R/G/B` at `0x18..0x20`, the flags union at `0x50`, old position/range at `0x58`/`0x64`, and `HasChanged` at `0x68`.
- The PDB's 170 `ASURA_CHUNKID` and 87 `ASURA_ENTITY_CLASSIFICATION` members match the local declarations exactly. The target dispatch maps every one of its 63 explicit/boundary chunk IDs into that chunk enum, but later-only members remain reference metadata rather than target support claims.
- The PDB does not contain `ASURA_RESOURCEFILE_TYPE_ID_PC`. It contains the Xbox 360 platform enum instead (`Environment`, `Character`, `Object`, `ObjectHierarchy`, `XPR`, `Botanicals`, `MaterialResponse`, `Carpet`, `StaticDecals`, and `StreamingSounds`), so it must not be used to number the target's PC resource subtypes.
- The PDB expresses the light flags as Xbox bitfields. On the little-endian target the corresponding raw masks run from `HasCorona=0x01` through `IsShadowVolume=0x40`, so the source intentionally serializes a `uint32_t` rather than relying on compiler bitfield order.

Every serialized structure used by the constructor/editor is now guarded by a size assertion, with critical offsets asserted separately. Shared types use the PDB names and layouts; target-only PC/versioned wire records carry explicit platform or version suffixes.

## Editor workflow

1. Build `LevelEditor.vcxproj`, or run `x64\Release\AsuraLevelEditor.exe`.
2. Choose **Open OBJ** for a new level, or **Open .PC** to load an original target-game level. OBJ levels use an upright, non-mirrored authoring view `(x, y, -z)` and export Env vertices as `(x, -y, -z)`. The `.PC` importer decodes the exact target Env module/strip/buffer layout and converts its negative-up Y axis only for display. Gameplay entity values—including sounds, lights, and spawnpoints—remain raw game coordinates, where negative Y is higher.
   When an original `.PC` is opened, the editor imports its version-3-through-5 `LITE` records, version-9 `PHON` records and matching sound-controller entities, version-0 `0x803A` spawnpoints, physical pickup objects (`0x0008`), assassination targets (`0x804F`), and position markers (`0x8052`). The latter three appear as orange, red, and purple source-backed entries with their true transforms. Pickup ObjectHierarchy meshes are resolved from their skin IDs and rendered in orange; their transforms and item IDs can be edited, and pickups can be created or deleted. Target and marker transforms remain editable while their not-yet-exposed class properties and delete operation stay locked. Its version-6/7 `SKYB` texture paths are resolved against type-2 `RSCF` texture resources in the same file and loaded directly into the existing skybox preview, including the cloud layer in slots 6/7. The preview also consumes the actual SKYB chunk version, RGB tint, Y-axis orientation, cloud-enable value, and both independent face-compatibility flags. The last supported WTHR chunk initializes the Rain toolbar toggle. Export uses that source file as the base: lights, sounds, spawnpoints, and newly created pickups are emitted; deleted pickup GUIDs are omitted; changed source-object transforms and pickup templates are patched at their exact class offsets; and every other byte of unsupported source payloads and chunks—including FOG—remains byte-exact. The default output name is `<source>_edited.PC`.
3. An opened `.PC` resolves its environment textures automatically from the active `TEXT`/`TXFL`/`MTRL` tables and embedded type-2 texture resources; no external material map or texture folder is required. The viewport uploads packed diffuse colours unchanged. Material-flag-`2` textures with TXFL bit `0x8` clear and no wet/additive/reflection flag are previewed as solid alpha-tested cutouts: the `10/255` test still exposes the sky/background through transparent texels, while surviving pixels use the target's opaque `saturate(2 * texture.rgb * prelight.rgb)` equation without an editor colour lift. Flag-`0x4` solid cutouts join this path rather than receiving the detail stage that over-brightened `fencing2.tga`. TXFL-bit-`0x8` blended materials and flags `0x1`, `0x80`, and `0x4000` retain the target Env composition, additive, sphere-map, and wet passes; non-cutout flag-`0x4` materials retain detail mapping. `GraphicNovel\detail.dds` and `SpecialFX\spheremap1.dds` are resolved from the working directory, beside the executable, the editor root, or the source-level folders. Wet WTHR plus flag `0x4000` substitutes the animated `SpecialFX\splash.dds` auxiliary stage. The preview intentionally ignores the legacy FOG chunk. An external material map remains available for OBJ-authored levels and explicit overrides; missing mapped textures receive stable diagnostic colours multiplied by vertex diffuse. **Skybox properties** edits the serialized SKYB v6/v7 format, RGB tint, orientation, paths, clouds, and compatibility flags. Both versions render the same target cube; v7 only adds the right-face mapping flag. The toolbar **Rain** checkbox overrides WTHR byte `+0x15`, immediately reloads wet materials and rain particles, supports undo/redo, and writes the chosen value into every supported source WTHR record on export. Original level-specific `SpecialFX\rn_p*.dds` rain sprites are resolved beside the editor or source level and rendered as six camera-centered, depth-tested layers even when clouds are disabled.
   For OBJ-authored levels, **Material map** and **Texture folder** provide the external material inputs. **Weapons donor** selects a target `.PC`; the editor imports placed pickup definitions and embedded ObjectHierarchy resources, then expands missing item profiles from the target item-to-model table. Export carries the required weapon, ammunition, pickup, texture, and sound resources into the custom level. **Skybox properties → Choose folder...** uses path basenames from the editable SKYB first and falls back to `fr`, `lf`, `bk`, `rt`, `up`, and `ch_04_sky`; **Use embedded** returns an original level to its source resources. Filename extensions are ignored because these assets contain DDS data even when the target path ends in `.tga` or `.bmp`.
4. Keep the target `MPChars.asr` in the editor's working directory, beside the executable, or two folders above an `x64\Release` executable. Choose **+ Spawn**, **+ Light**, **+ Sound**, or **+ Pickup**, then click visible Env geometry. Placement and left-drag use a two-sided nearest-triangle BVH raycast, update full XYZ on slopes and vertical surfaces, retain the current position on misses, and do not jump when a marker is merely clicked. A sound's WAV, repeat flag, and one-shot **Play/Stop** preview are available in its inspector; imported sounds can preview their embedded type-3 WAV resource. A pickup uses the selected item's donor asset profile but constructs a fresh, fully versioned `0x0008` body with canonical class defaults, identity orientation, 100 health, zero blocked links, and initialized state/animation fields.
5. Entities are listed alphabetically by name and then type without changing source document order. Edit position, rotation, and type-specific properties in the inspector. Pickup item types are selected from an alphabetically sorted list of available donor-backed items. Spawn points expose camera pitch/yaw plus verified team and game-mode checkboxes while preserving unknown mask bits; a `Camera-only` marker draws an arrow along its serialized camera direction. Lights expose RGB, independent brightness and range values, inner range, shadow strength, a world-axis bounding box, and all seven named PC flag masks, including `Affects environment`, while avoiding misleading direction/cone and brightness-over-range preview controls. The light dialog enables bounding-box fields only for `Use bounding box`, and switches from RGB/brightness to shadow strength for `Shadow volume`; the main inspector likewise replaces its brightness row with shadow strength for shadow-volume lights. Selected lights and sounds use radial range globes, and a selected light with `Use bounding box` also draws its world-axis box. Only the selected entity bypasses Env occlusion; unselected markers and models remain hidden behind geometry.
6. Use Ctrl+C/Ctrl+V to copy and paste authorable entities, Ctrl+Z/Ctrl+Y to undo and redo, and Delete to remove the selection. Dragging is recorded as one transaction, not one entry per mouse move. Save a binary `.alev` project and choose **Export .PC**.

The current `.alev` format is version 11 so the original `.PC` source path, source light header, complete imported phonon/controller and spawn records, pickup inventory and canonical item asset profiles, source-backed object/target/marker metadata, the actual SKYB chunk version, both independent SKYB compatibility flags, and editable WTHR rain state survive project save/load. A custom project's saved Weapons donor is re-read on open so its pickup models are restored. Version-1 through version-10 projects remain readable; version-8 pickup templates are recovered from their source `.PC` when it is available, unsupported older entity records are omitted, and older sounds default to looping.

The selected light is visualized as a complete three-ring globe at its exact radial range, matching the target's omnidirectional runtime evaluation. Unselected lights retain only their normal entity markers and obey Env depth.

The selected sound is visualized with a blue wire globe at its maximum radius. Unselected sounds retain only their normal entity markers.

Spawnpoints with team mask `5` (Russian + Deathmatch) render the actual `russian_soldier9` mesh decoded from `MPChars.asr`; team mask `3` (German + Deathmatch) renders the German preview. The puppet is lit, faction-tinted, anchored at the spawn position, and rotated from the serialized gameplay/camera forward vector's pitch and yaw. Unselected puppets obey Env depth; only the selected puppet bypasses it while retaining self-occlusion. Clicking inside its projected bounds selects it. A newly placed spawn defaults to mask `5`. An unsupported mask or unavailable/incompatible archive retains the marker fallback.

Physical pickups use the same lit entity-model pass, but their meshes come from subtype-5 ObjectHierarchy resources inside the opened `.PC`. Their full pitch/yaw/roll transform, target negative-up coordinate conversion, self-occlusion, projected-bounds selection, and GDI fallback wireframe all use the decoded model. A missing or unrecognized hierarchy keeps the explicit orange marker fallback.

Viewport controls:

- Double-click an entity in the list: center and zoom the camera on its rendered model, marker, or bounds
- Right-drag: orbit
- Middle-drag: pan
- Mouse wheel: zoom
- Left-click: select/place
- Left-drag a marker: move it across the Env surface in XYZ
- Ctrl+C / Ctrl+V: copy / paste entity
- Ctrl+Z / Ctrl+Y: undo / redo
- Delete: remove selected entity

## Current boundaries

- Spawn puppets are static editor previews of the character resource's authored vertex positions. They do not add `MPChars.asr` to exported levels and do not run the game's animation/skeleton system.
- Pickup creation and item switching require a renderable ObjectHierarchy in either the opened source level or the selected Weapons donor. The editor derives the canonical file/skin/animation hashes from the target mapping and retail ASR paths; it does not offer enum members whose model resource is absent.
- The viewport uses a D3D11 child swap chain. Exact positions, normals, UVs, packed diffuse colours, material-grouped indices, and resolved DDS resources are uploaded when the environment or material inputs change; camera and entity interaction otherwise update small dynamic buffers. The cached GDI renderer remains as a device-initialization fallback. Dense meshes are not sparsely sampled. OBJ export still builds render/collision data through the constructor; imported `.PC` export retains the source render/collision chunks.
